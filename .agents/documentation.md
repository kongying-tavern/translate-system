# 文档维护指南

> 本篇说明文档的受众分区、命名、结构与写作风格。新建或修改任何 .md 前先读这篇。

## 受众与位置

| 受众 | 位置 | 内容 |
|------|------|------|
| AI | `.agents/`（本目录） | 分专题的高密度开发约定，AGENTS.md 是总索引 |
| 开发者 / 用户 | `docs/` 与 `README.md` | 面向人的使用、部署、权限等说明 |

- 同一主题不要两处重复写；一方引用另一方即可
- 功能改动时同步对应分册，新增分册必须在 AGENTS.md 目录表登记

## 文件命名

- 全部小写 kebab-case：如 `open-api.md`、`import-export.md`
- 按功能命名，避免 `-and-` 复合词与冗余前缀：
  - workflow.md（不是 workflows-and-faq.md）
  - slug.md（不是 slug-and-encoding.md）
  - open-api.md（不是 apikey-open-api.md）
- 已跟踪文件用 `git mv` 改名，保留历史

## 结构模板

```markdown
# 标题

> 一句话定位语：本篇说明……。

## 正文小节
…（要点 / 表格）

## 相关文档

- [链接](文件) —— 一句话用途
```

- 头部只放一句定位语，不放读者标签和堆叠的相关链接
- 「相关文档」独立成节放文末，逐行列出并可附一句用途

## 写作风格

- 不用「唯一真相 / 单源 / 单飞」这类术语黑话——直说哪个文件、哪条规则
- 一个要点占一行；同一主题的多方面信息拆成子条目或表格
- 单行超过 ~150 字通常说明里面塞了多个要点，应当拆开
